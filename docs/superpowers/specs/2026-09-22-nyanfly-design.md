# nyanfly 설계

- 작성일: 2026-09-22
- 상태: 확정 (구현 착수)

## 1. 개요

냥이를 대포로 날려 거리를 겨루는 원버튼 물리 아케이드. 발사 전 각도와 파워를 게이지로
정하고, 비행 중에는 구름·새·지면에 닿는 순간에 맞춰 버튼을 눌러 가속을 이어간다.
한 판에서 번 츄르로 업그레이드를 사서 다음 판의 기록을 늘린다.

기존 프로젝트(냥타의 고군분투, 실시간 탑다운 서바이벌)와는 조작·시점·재미의 축이
모두 다르지만 세계관과 아트 톤은 이어받는다.

## 2. 핵심 결정: 결정론 시뮬레이션

시뮬 계층과 표현 계층을 완전히 분리한다. 한 판의 결과는 `{seed, levels, inputs}`만으로
언제 어디서나 똑같이 재현된다. 이 구조에서 다음이 따라 나온다.

- 상위 기록의 유령 리플레이 재생
- 서버에서 기록을 재현해 검증 (클라이언트 점수를 믿지 않아도 된다)
- 데일리 코스의 공정성 보장

시뮬을 나중에 결정론으로 바꾸는 것은 사실상 불가능하므로 1일차부터 적용한다.

### `js/sim/` 금지 규칙

1. `Math.random()` 금지 — 정수 시드를 받는 자체 RNG/해시만 사용
2. `Date.now()`, `performance.now()` 금지 — 시간은 프레임 번호로만 표현
3. DOM·Canvas 접근 금지
4. `Math.sin/cos/tan/pow/exp` 금지 — IEEE 754가 정확도를 규정하지 않아 플랫폼마다
   마지막 비트가 달라질 수 있다. 대신 사칙연산만 쓰는 다항식 근사(`js/sim/trig.js`)를
   쓴다. `Math.sqrt`, `Math.floor`, `Math.round`, `Math.abs`, `Math.imul`은 정확도가
   규정되어 있어 허용한다.

### 루프

고정 타임스텝 `DT = 1/120`초 + 누적자. 실제 경과 시간을 누적해 120Hz 단위로만 시뮬을
돌리고, 렌더는 남은 잔여 시간으로 위치를 보간한다. 모니터 주사율과 무관하게 결과가 같다.

### 입력 기록

입력은 상태가 아니라 사건으로 기록한다. 한 판의 기록은 버튼을 누른 프레임 번호의 배열
뿐이다(`inputs: [17, 43, 51, ...]`). 한 판에 많아도 수백 개라 1KB 미만이다.
시뮬 로직을 바꾸면 과거 리플레이가 깨지므로 `SIM_VERSION`을 함께 저장하고 랭킹을
버전별로 분리한다.

## 3. 물리 모델

단위는 픽셀, 10px = 1m. y축은 위가 양수이며 렌더 계층에서 화면 좌표로 변환한다.

- 중력 `G = 1000 px/s²`
- 공기저항: 속도에 비례하는 선형 감쇠 `v -= v * drag * DT`. 제곱 저항은 결정론에는
  문제없지만 업그레이드 체감을 선형으로 두는 편이 조율하기 쉽다.
- 지형: 노드 간격 110px의 값 노이즈 2옥타브. 노드 높이는 `hash32(seed, i)`로 즉석
  계산하므로 지형 배열을 들고 있지 않아도 되고 길이 제한도 없다. 노드 사이는
  smoothstep으로 보간해 기울기가 연속이다(기울기는 해석적 미분으로 구한다).
- 지면 충돌: 기울기에서 법선을 구해 반사시키고, 접선 성분에는 마찰을 건다.
  법선 속도가 작아지면 `grounded` 상태로 넘어가 구르기로 처리한다. 구르기에서는
  중력의 접선 성분이 더해지므로 내리막에서 자연히 가속한다.
- 종료: 접지 상태에서 속도가 25px/s 아래로 45프레임 유지되면 종료. 안전장치로
  `MAX_FRAMES = 120 * 100`(100초) 상한을 둔다.

## 4. 공중 오브젝트

슬롯 폭 520px마다 최대 하나. 종류와 위치는 `hash32(seed, slot)`로 즉석 계산하고,
소비 여부만 런당 `Uint8Array`에 기록한다. 화면 밖 슬롯은 아예 계산하지 않는다.

| 종류 | 효과 | 타이밍 창 |
|------|------|-----------|
| 구름 | 위로 튕겨 올린다 | 있음 |
| 새 | 앞·위로 밀어낸다 | 있음 |
| 링 | 통과하면 수평 가속 | 없음 |

## 5. 타이밍 창

구름·새·지면에 닿으면 기본 효과가 적용되고 동시에 `±window` 프레임의 보너스 창이 열린다.
창 안에서 버튼을 누르면 접촉 프레임과의 차이에 비례한 추가 가속이 붙는다. 접촉 직전에
누른 클릭도 창 안이면 접촉 순간에 소급 적용되므로, 미리 누르든 맞춰 누르든 공정하다.
차이가 창의 30% 안이면 `완벽`, 그 밖은 `좋음`. 창을 놓치면 콤보만 끊기고 벌점은 없다.

## 6. 업그레이드 경제

레벨 0~8, 비용은 `base * 1.55^level`. 전부 시뮬에 영향을 주므로 리플레이에 함께 저장한다.

| 항목 | 효과 |
|------|------|
| 대포 화력 | 발사 초속 상승 |
| 조준 훈련 | 각도·파워 게이지 속도 하락(맞추기 쉬워짐) |
| 유선형 | 공기저항 하락 |
| 젤리 발바닥 | 지면 반발 상승 |
| 박자 감각 | 타이밍 창 확대 |
| 츄르 사랑 | 츄르 획득량 상승 |

츄르 획득량은 `거리(m) * rate`. 초반 30m에서 후반 3000m까지 두 자릿수 성장을 목표로
하며, 업그레이드만으로는 절반까지만 오르고 나머지는 타이밍 실력에서 나오게 배분한다.

## 7. 데이터와 랭킹

- 로컬 진행도: `localStorage`에 `{version, churu, levels, best}`. 조작해도 남에게
  영향이 없는 값이므로 암호화하지 않는다.
- 랭킹: `js/net/leaderboard.js`가 인터페이스를 제공하고, `js/net/config.js`에 Supabase
  설정이 없으면 로컬 랭킹으로 동작한다. 서버 스키마는 `{seed, sim_version, levels,
  inputs, distance, nickname}`을 받고, 거리는 신뢰하지 않고 재현으로 검증한다.
- 닉네임은 `textContent`로만 출력한다. `innerHTML`에 넣어야 할 때는 이스케이프한다.

## 8. 렌더 예산

- 화면에 동시에 존재하는 물체가 수십 개 수준이라 프레임 부담이 작다. 그럼에도 기존
  프로젝트의 규칙은 유지한다: 반복해서 그리는 그림은 오프스크린 캔버스에 캐시,
  화면 밖은 그리지 않기, 매 프레임 새 배열·객체 만들지 않기, DPR 상한.
- 입자와 화면 흔들림은 렌더 계층에만 존재한다. 시뮬 결과에 영향을 주지 않으므로
  여기서는 `Math.random()`을 써도 된다.
- 목표: 1080p에서 `render` 4ms 이하.

## 9. 범위

1차 구현에 포함: 발사 2단계, 비행 물리, 타이밍 창, 지형·오브젝트 생성, 결과 화면,
업그레이드 상점, 로컬 저장, 로컬 랭킹.

1차에서 제외: Supabase 실제 연동(인터페이스만), 유령 리플레이 재생, 데일리 코스,
서버 검증. 모두 결정론 구조 위에 나중에 얹을 수 있다.
